Never miss a GitHub review request

Someone is blocked until you review their pull request, and the only sign is one more email between a hundred others. Here are the ways to make review requests impossible to miss on a Mac, and how Pullbell does it.

Why review requests get lost

GitHub sends review requests the same way as everything else: as a notification in the web inbox and, depending on your settings, an email. If you are on several teams, a review request through a team looks no different from an @-mention in a long thread or a bot comment. The result is review requests that sit for days.

Option 1: tune GitHub's own settings

Start with what GitHub gives you. In your GitHub notification settings you can choose how you are notified (web, email, mobile) and whether to receive notifications for everything you watch or only when you are participating. Use the inbox filters on github.com/notifications to look at review requests only. It costs nothing, but you have to remember to open the page.

Option 2: a banner the moment it happens

Pullbell gives review requests the highest priority. A review requested notification, whether someone asked for you directly or through one of your teams, raises a macOS banner and counts towards the n in the menu bar count n+m. Click the banner and the pull request opens in your browser and is marked as done (and read on GitHub).

Pullbell checks GitHub every 3 minutes by default, or every 1, 5 or 10 if you change it.

Option 3: the list of PRs waiting for you

Banners can be dismissed by accident. Pullbell also keeps a Waiting for my review submenu, built from a GitHub search for open PRs that request your review, and ⌃⌘P opens it in a window where you can type to filter. Nothing leaves the list until the review request is gone from GitHub, so it works as a to-do list.

Option 4: a daily digest

If you like to clear reviews at a set time, turn on the daily digest in Settings, then Alerts. Once a day, at the hour you choose (06 to 12), Pullbell raises one banner listing the review requests still waiting on you. It is off by default.

Keep the noise low so the bell means something

A bell you learn to ignore is worse than none. Pullbell only rings for things that need you, keeps bots and the rest in an FYI list, ignores your own activity and merges a burst of comments on one PR into a single banner. Read more in how to reduce GitHub notification noise.

Get started

Download Pullbell from the latest release, clear the quarantine flag once (xattr -dr com.apple.quarantine /Applications/Pullbell.app) and sign in. If you are choosing between tools, see Pullbell vs Gitify and Octobox.

Frequently asked questions

Does a review request through a team count?

Yes. Pullbell treats a review request as a "needs you" event whether it was addressed to you directly or to one of your teams.

Can I get a daily reminder of waiting reviews?

Yes. The optional daily digest raises one banner a day, at an hour you choose, with the review requests still waiting on you. It is off by default.

Do I need to give Pullbell access to my repos?

Sign-in uses GitHub's device flow with the notifications, repo and read:org scopes. The token is stored in your macOS Keychain and used only to call GitHub's API from your Mac.

What if my organization uses SAML single sign-on?

The menu shows an "Authorize for ORG" line. Click it to authorize Pullbell for that organization. Other repos keep working meanwhile.
