Pullbell / GitHub pull request notifier for macOS

A GitHub pull request notifier for macOS

If you open pull requests all day, the questions are always the same: did anyone review it, is it ready to merge, did it just get a conflict, and what is waiting for me? Pullbell answers them from the menu bar.

Know when your pull request changes state

Most notification tools tell you that something was said on your PR. Pullbell also tells you when the PR itself changes state. It watches your open PRs (is:pr is:open author:@me) and raises a banner on two transitions:

  • Ready to merge: approved, all checks green, no conflict, not a draft.
  • Conflict: the PR just became unmergeable because of a merge conflict.

These fire when the state changes, not on every poll, and Pullbell remembers the last state so a restart does not repeat them. Approvals and changes-requested reviews each ring too, and comments and replies from people (not bots) come with the first part of the text in the banner.

See all your open PRs at a glance

The My open PRs submenu lists each PR with its CI state (green, failing or running) and review state (approved, waiting, changes requested, draft, conflict). Press ⌃⌘P to open the same list in a searchable window. It also shows Waiting for my review, the PRs where someone requested your review (review-requested:@me), so you do not have to search GitHub for them.

Be told when a deploy fails

Pullbell can also watch the default branch of the repos you follow. When a workflow run fails and its name matches a pattern (default deploy|release|publish, editable in Settings), you get a banner. Routine CI run notifications, which GitHub sends once per workflow run you trigger, are ignored by default so they do not bury real events. Failures that matter still appear through the deploy alert and the CI marker on My open PRs.

Choose which repos to watch

By default Pullbell watches everything you get notifications for. If you are in many organizations you can limit it to the repos of the GitHub teams you pick plus any extra repos you type as owner/name. Muted repos are always ignored. If an organization uses SAML single sign-on, the menu shows Authorize for ORG; click it once and that org works too, while your other repos keep working in the meantime.

Set it up

Download the DMG from the latest release, clear the quarantine flag once with xattr -dr com.apple.quarantine /Applications/Pullbell.app, open it and sign in with GitHub. Needs macOS 13 or newer.

If your problem is noisy notifications rather than missing ones, read how to reduce GitHub notification noise. For the menu bar basics see GitHub notifications in the Mac menu bar.

Frequently asked questions

Does Pullbell notify me when my PR is approved?

Yes. An approving review rings by default, and a separate "Ready to merge" banner fires when the PR is approved, checks are green, there is no conflict and it is not a draft.

Can it show PRs waiting for my review?

Yes. The "Waiting for my review" submenu and the ⌃⌘P window list PRs where your review is requested, directly or through a team.

Does it notify me of CI results?

Not for every run. GitHub's per-run CI notifications are ignored by default. You get a banner when a deploy, release or publish workflow fails on a watched default branch, and My open PRs shows a CI marker per PR.

Will I get a banner for my own comments?

No. Your own comments, reviews and pushes never ring.

Does it work with GitHub Enterprise Server?

The repository does not document support for GitHub Enterprise Server, so it is not claimed here. Pullbell is built for github.com.
